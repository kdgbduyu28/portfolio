Engineering stories

The double charge

ProblemRetries created a new idempotency key, so some customers were charged twice. FixMade every retry reuse the payment's original idempotency key. ResultA retried payment no longer creates a second charge.

4M reads a day

ProblemDatabase reads were far higher than the traffic explained. FixTraced the reads to a client loop and fixed it on the server. ResultAbout 4M fewer database reads every day.

One-command releases

ProblemFour apps each needed builds for TestFlight, the App Store and Google Play. FixBuilt one release pipeline that covers every app and store. ResultOne command ships all four apps.

Engineering stories

Permissions in the database

Problem
Many clinics share one database, so a bug in any app could expose another clinic's data.
Fix
Enforced every permission in PostgreSQL with row-level security.
Result
720+ automated database tests prove each clinic sees only its own data.

No double-booking

Problem
Two staff members can book the same slot at the same time.
Fix
Added a database constraint that rejects overlapping bookings.
Result
Double-booking is impossible, whichever app sends the request.

An audit log no client can skip

Problem
A log written by the apps only works if every app remembers to write it.
Fix
Moved audit logging into the database itself.
Result
Every change is recorded, and no client can skip it.

Engineering stories

Messy place names

Problem
Sources write the same town many ways, like "Sta. Cruz" or "City of Cebu".
Fix
Matched every name to a list of 1,736 official places.
Result
Prices land in the right town.

One broken source doesn't stop the rest

Problem
A bad government PDF could break the whole update.
Fix
Made each of the 19 sources fail on its own.
Result
A broken source skips only itself; the rest still update.
